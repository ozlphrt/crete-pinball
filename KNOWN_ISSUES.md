# Crete Pinball — Known Issues Register

**Current Phase:** Phase 05 (Audio, Visual Effects, Tutorial, Localization & Accessibility)  
**Status:** Active  

| Issue ID | Severity | Phase Identified | Component | Description | Status / Mitigation |
|---|---|---|---|---|---|
| ISS-001 | Low | Phase 00 | Build / Bundling | Production build reports single chunk > 500 kB due to bundled Phaser engine and geographic data (`dist/assets/index-*.js` ~ 2.1 MB uncompressed, ~480 kB gzipped). | Expected for monolithic game bundle; will implement code-splitting via dynamic import / Rollup `manualChunks` in Phase 07 (Release & PWA Optimization). |
| ISS-002 | Low | Phase 00 | Browser Testing | Physical mobile touch hardware latency and real iOS Safari home-bar gesture interactions cannot be automated via headless Playwright. | Automated mobile emulation passes 100% on iPhone 13 (WebKit) and Pixel 5 (Chromium); physical touch latency validation scheduled during physical playtesting. |
| ISS-003 | Low | Phase 01 | Orientation | Orientation prompt on desktop previously triggered if window was resized below 900px wide. | **RESOLVED**: `OrientationHandler` checks `(isTouchDevice || isMobileAgent)` so desktop pillarboxed layout is never blocked by mobile rotation prompt. |
| ISS-004 | Low | Phase 02 | Physics / Tuning | Crete's authentic width ($432$ world units) spans approximately $48\%$ of the arena width ($900$ units). With unrestricted paddle movement, rapid player swipes across screen could transfer huge impulses. | **RESOLVED**: Paddle horizontal speed restrictions removed to directly follow touch/mouse without smoothing or inertia. Momentum transfer is independently capped via `maxPaddleTransferSpeed` ($380$ u/s) and dynamic intrusion safeguard prevents tunneling. |
| ISS-005 | Low | Phase 02 | Visuals / Zoom | In standalone Explore mode, zooming past $3.0\times$ on small islets reveals the 2.0-unit polygon simplification deviation budget. | Working as designed per CC0 Natural Earth dataset specification; collision segments strictly track the authentic 2.0-unit boundary. |
| ISS-006 | Low | Phase 04 | Input / Key Bindings | Diagnostic overlay toggle (`KeyB`) previously conflicted with developer power bounce test key. | **RESOLVED**: `KeyB` retained for bounding boxes/diagnostics, `KeyE` assigned for desktop power bounce activation alongside double-click and touch double-tap. |
| ISS-007 | Low | Phase 04 | Accessibility / Motion | Cinematic slow-motion passage rate changes could cause motion sensitivity on rapid triggers. | **RESOLVED**: `TimeDilationController` queries `prefers-reduced-motion` and suppresses time dilation when enabled; hysteresis and a 6s simulation cooldown prevent rapid re-triggering. |
| ISS-008 | Low | Phase 05 | Audio / Browser Autoplay | Modern mobile browsers block audio playback until an explicit user interaction occurs. | **RESOLVED**: `AudioManager` implements gesture-based unlock listeners (`pointerdown`, `keydown`, `touchstart`) so audio initializes cleanly on first tap. |
| ISS-009 | Low | Phase 05 | Audio / Testing | Headless browser test environments lack physical audio output devices and start AudioContext in a suspended state. | **RESOLVED**: `AudioManager` handles suspended or mocked audio contexts safely with graceful fallback, preventing crashes during automated testing. |
| ISS-010 | Low | Phase 05 | UI / Animation Stability | Transform-based CSS keyframe entrance animations on modals previously delayed Playwright actionability checks on mobile emulators. | **RESOLVED**: Modal entrance animations use pure opacity fade (`animation: 0.15s ease-out`), ensuring instantaneous element stability during automated testing while maintaining smooth visual aesthetics. |
| ISS-011 | Medium | Phase 05 | Audio / Reset Lifecycle | AudioContext autoplay warnings and silent audio on subsequent game resets when gesture listener unhooked prematurely. | **RESOLVED**: Disabled duplicate Phaser sound manager (`audio: { noAudio: true }`), maintained persistent gesture listeners until `state === 'running'`, guarded `startAmbience()` with async resume resolution, and wired `resumeContext()` to pointer down and restart actions. |
| ISS-012 | Medium | Phase 05 | Graphics / Visibility | Coastline outlines were overly subdued against dark ocean backdrop following glare reduction. | **RESOLVED**: Added dedicated vector coastline outline layer at depth 3 in `GeographyRenderer` featuring a 1.2px marine cyan core (`0x38bdf8`) with an atmospheric under-glow, producing crisp, clearly visible shorelines without glare. |
